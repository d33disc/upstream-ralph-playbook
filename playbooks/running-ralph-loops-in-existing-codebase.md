# Playbook: Running Ralph Loops in an Existing Codebase

A step-by-step guide for beginners on how to kick off, run, and complete Ralph loop(s) in a project that already has Ralph set up.

---

## Overview

This playbook covers the workflow for joining an existing project that uses the Ralph methodology. You'll learn how to understand the current state, set up your environment, run loops, monitor progress, and complete work successfully.

If you need to set up Ralph from scratch, see [Starting a New Ralph Loop](./starting-a-new-ralph-loop.md) first.

---

## What You Need to Know Before Starting

### Required Knowledge

- **Basic command-line usage** — running scripts, navigating directories, reading terminal output.
- **Basic Git** — cloning, branching, committing, pushing, checking diffs.
- **How to read Markdown files** — all Ralph configuration and documentation is in Markdown.
- **Understanding of the project's language/framework** — you need to validate that Ralph's output is correct.
- **Basic debugging** — reading error messages, identifying failures in logs, correcting issues.

### Key Ralph Concepts

| Term | What It Means |
| --- | --- |
| **Ralph Loop** | A bash loop that repeatedly feeds a prompt to Claude, which reads specs, implements a task, commits, and exits — then the loop restarts with fresh context |
| **Spec** | A Markdown file in `specs/` describing _what_ to build (outcomes, not implementation details) |
| **Implementation Plan** | `IMPLEMENTATION_PLAN.md` — a prioritized task list generated by Ralph, updated each iteration |
| **AGENTS.md** | Operational notes loaded every iteration — tells Ralph how to build, test, and run the project |
| **Planning Mode** | Loop mode that analyzes specs vs. code and generates/updates the plan (no implementation) |
| **Building Mode** | Loop mode that picks tasks from the plan, implements them, runs tests, commits |
| **Backpressure** | Tests, lints, typechecks — the gates that force Ralph to produce correct output |

## Step 1: Review the Existing Codebase

### Clone the Repository

```bash
git clone https://github.com/your-org/your-project.git
cd your-project
```

### Understand the Project Layout

Look for Ralph's standard files in the project root:

```bash
ls -la PROMPT_*.md AGENTS.md IMPLEMENTATION_PLAN.md loop.sh specs/
```

Expected structure:

```
project-root/
├── loop.sh                    # The loop script (may also be loop_streamed.sh)
├── PROMPT_build.md            # Build mode instructions
├── PROMPT_plan.md             # Plan mode instructions
├── AGENTS.md                  # Operational guide (build/test/run commands)
├── IMPLEMENTATION_PLAN.md     # Current task list (generated by Ralph)
├── specs/                     # Requirement specifications
│   ├── 01-topic-a.md
│   └── 02-topic-b.md
└── src/                       # Application source code
```

### Read the Key Files

Read these files in order to understand the project's current state:

1. **`README.md`** — Project overview and setup instructions.
2. **`AGENTS.md`** — How to build, test, and run the project. This tells you the exact commands.
3. **`IMPLEMENTATION_PLAN.md`** — What has been done and what remains. Review completed vs. pending tasks.
4. **`specs/`** — Browse the spec files to understand the requirements.
5. **`PROMPT_build.md` / `PROMPT_plan.md`** — Understand what instructions Ralph receives each iteration.

## Step 2: Set Up the Environment

### Install Prerequisites

1. **Claude CLI** — Install Anthropic's CLI tool:

   ```bash
   npm install -g @anthropic-ai/claude-cli
   ```

   Verify it's installed:

   ```bash
   claude --version
   ```

2. **Project dependencies** — Follow the project's setup instructions. Common patterns:

   ```bash
   # Node.js projects
   npm install

   # Python projects
   pip install -r requirements.txt
   # or
   python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt

   # Go projects
   go mod download

   # Ruby projects
   bundle install
   ```

3. **Verify the build** — Run the commands from `AGENTS.md`:

   ```bash
   # Example — check AGENTS.md for your project's actual commands
   npm run build
   npm test
   npm run lint
   ```

   > **Important:** Make sure the project builds and tests pass _before_ starting Ralph. If they don't, fix issues first or note them so Ralph can address them.

### Set Up a Sandbox (Recommended)

Ralph runs with `--dangerously-skip-permissions`, which bypasses all Claude safety prompts. Use an isolated environment:

- **Docker** — Run in a container with only necessary credentials.
- **Remote sandboxes** — [Fly Sprites, E2B, or exe.dev](../references/sandbox-environments.md).
- **At minimum** — Use a dedicated branch and review commits before merging.

## Step 3: Locate and Review Ralph Loop(s)

### Find the Loop Script

The loop script is typically at the project root:

```bash
ls loop*.sh
```

Common variants:

| Script | Description |
| --- | --- |
| `loop.sh` | Standard loop — runs Claude, pushes changes, repeats |
| `loop_streamed.sh` | Enhanced version with color-coded streaming output |

### Verify the Script Is Executable

```bash
chmod +x loop.sh
# and/or
chmod +x loop_streamed.sh
```

### Review Loop Configuration

Open `loop.sh` and check:

- **Which model is configured** — Look for `--model opus` or `--model sonnet`.
- **Which prompt files it references** — Should be `PROMPT_plan.md` and `PROMPT_build.md`.
- **Git push behavior** — Most scripts push after each iteration.

### Review the Current Plan

```bash
cat IMPLEMENTATION_PLAN.md
```

Check:

- What tasks are marked complete?
- What tasks are still pending?
- Are there any noted bugs or blockers?

## Step 4: Kick Off a Ralph Loop

### Create a Working Branch

Always work on a dedicated branch:

```bash
git checkout -b ralph/my-feature
# or use an existing Ralph branch
git checkout ralph/existing-branch
```

### Choose Your Mode

| Mode | When to Use | Command |
| --- | --- | --- |
| **Planning** | No plan exists, plan is stale, or specs have changed significantly | `./loop.sh plan` |
| **Building** | A valid plan exists with pending tasks | `./loop.sh build` |

### Start the Loop

**Planning mode** (generates/updates the implementation plan):

```bash
./loop.sh plan
```

**Building mode** (implements tasks from the plan):

```bash
./loop.sh build
```

**Building mode with iteration limit** (stops after N tasks):

```bash
./loop.sh build 10    # Stop after 10 tasks
./loop.sh 20          # Shorthand: build mode, max 20 tasks
```

**Using the streamed variant** (readable color-coded output):

```bash
./loop_streamed.sh build 10
```

### What Happens When the Loop Starts

Each iteration follows this lifecycle:

1. **Orient** — Ralph reads `specs/*` to learn the requirements.
2. **Read plan** — Ralph reads `IMPLEMENTATION_PLAN.md` for the current task list.
3. **Select** — Ralph picks the most important pending task.
4. **Investigate** — Ralph searches existing code ("don't assume not implemented").
5. **Implement** — Ralph writes code using subagents for parallel file operations.
6. **Validate** — Ralph runs tests/build/lint (backpressure) to verify the work.
7. **Update plan** — Ralph marks the task done and notes any discoveries.
8. **Update AGENTS.md** — Ralph records any operational learnings.
9. **Commit and push** — Changes are committed and pushed to Git.
10. **Loop restarts** — Context is cleared; next iteration starts fresh.

## Step 5: Monitor and Debug the Run

### Watch the Output

Monitor the terminal for:

- **Task selection** — Which task did Ralph pick? Is it the right priority?
- **Test results** — Are tests passing? Look for build/lint/typecheck output.
- **Commit messages** — Ralph commits after each successful task. Review what changed.
- **Errors** — Watch for repeated failures, circular behavior, or unexpected changes.

### Check Git History

In a separate terminal, monitor what Ralph is committing:

```bash
# Watch for new commits
git log --oneline -10

# See what changed in the last commit
git diff HEAD~1

# See the current state of the plan
cat IMPLEMENTATION_PLAN.md
```

### Common Issues and Solutions

| Symptom | Likely Cause | Solution |
| --- | --- | --- |
| Ralph keeps failing on the same task | Tests or build are broken in a way Ralph can't fix | Stop the loop (Ctrl+C), investigate manually, fix the issue, restart |
| Ralph picks low-priority tasks | Plan prioritization is off | Stop the loop, run `./loop.sh plan` to regenerate the plan |
| Ralph reimplements existing code | It's not searching before implementing | Check that `PROMPT_build.md` includes "don't assume not implemented" |
| Ralph generates wrong patterns | No existing patterns to follow | Add utility code or examples in `src/lib/` for Ralph to discover |
| Loop pushes but no changes | Ralph found nothing to do or couldn't complete a task | Review terminal output; check if all plan items are done |
| Build/test commands are wrong | `AGENTS.md` has incorrect commands | Update `AGENTS.md` with the correct build, test, and lint commands |

### Using Escape Hatches

- **Ctrl+C** — Stop the loop immediately.
- **`git reset --hard`** — Revert any uncommitted changes.
- **`git revert HEAD`** — Undo the last commit if Ralph made a bad change.
- **Delete and regenerate the plan** — If the plan is wrong, delete `IMPLEMENTATION_PLAN.md` and run `./loop.sh plan`.

## Step 6: Complete the Loop

### Verify the Output

Once the loop has finished (or you've stopped it), verify the results:

1. **Review `IMPLEMENTATION_PLAN.md`** — Are all intended tasks marked complete?

   ```bash
   cat IMPLEMENTATION_PLAN.md
   ```

2. **Run the full test suite** — Verify everything passes:

   ```bash
   # Check AGENTS.md for your project's actual commands
   npm test          # or pytest, go test, etc.
   npm run build
   npm run lint
   ```

3. **Review the Git log** — Check all commits Ralph made:

   ```bash
   git log --oneline
   ```

4. **Review the diff against the base branch** — Inspect all changes:

   ```bash
   git diff main...HEAD
   ```

5. **Spot-check generated code** — Open key files and verify:

   - Code quality meets your standards.
   - No placeholder or stub implementations.
   - No security issues introduced.
   - Patterns are consistent with the existing codebase.

### Handle Post-Processing

Depending on your project, you may need to:

- **Run integration tests** — If the project has tests beyond unit tests.
- **Update documentation** — Review and update any project-level docs.
- **Clean up `IMPLEMENTATION_PLAN.md`** — Remove completed items if the file has grown large.
- **Review `AGENTS.md`** — Ensure operational notes are still accurate and concise (target ~60 lines).

### Merge or Continue

- **If all tasks are complete:** Create a pull request from your Ralph branch to the main branch. Review the full diff before merging.
- **If more tasks remain:** Continue the loop with `./loop.sh build`.
- **If the plan needs revision:** Run `./loop.sh plan` to regenerate, then continue building.

## Step 7: Make Changes or Extend

### Modifying Specs

If you need to change requirements:

1. Edit the relevant spec file in `specs/`.
2. Delete or regenerate `IMPLEMENTATION_PLAN.md`:

   ```bash
   echo "" > IMPLEMENTATION_PLAN.md
   ./loop.sh plan
   ```

3. Review the new plan, then switch to building:

   ```bash
   ./loop.sh build
   ```

### Adding New Features

1. Write a new spec file following the naming convention:

   ```
   specs/NN-kebab-case.md
   ```

2. Apply the "One Sentence Without 'And'" test — if your spec needs "and" to describe what it does, split it into multiple specs.
3. Regenerate the plan and run the build loop.

### Adjusting Ralph's Behavior

| Want to Change | Where to Adjust |
| --- | --- |
| Task priorities | Edit `IMPLEMENTATION_PLAN.md` or regenerate with `./loop.sh plan` |
| Build/test commands | Edit `AGENTS.md` |
| How Ralph approaches work | Edit `PROMPT_build.md` — add guardrails using `999...` numbering |
| What Ralph builds | Edit spec files in `specs/` |
| Code patterns Ralph follows | Add utility code or examples in `src/lib/` |

## Quick-Reference: Common Commands

```bash
# Planning mode (generate/update implementation plan)
./loop.sh plan

# Building mode (implement tasks, unlimited)
./loop.sh build

# Building mode (limit to 10 tasks)
./loop.sh build 10

# Building mode shorthand (20 tasks)
./loop.sh 20

# Streamed output variant
./loop_streamed.sh build 10

# Stop the loop
Ctrl+C

# Revert uncommitted changes
git reset --hard

# Check what Ralph committed
git log --oneline -10
git diff HEAD~1

# Review the current plan
cat IMPLEMENTATION_PLAN.md

# Review operational notes
cat AGENTS.md
```

## Troubleshooting Checklist

If things aren't working, check these in order:

- [ ] Is the Claude CLI installed and authenticated? (`claude --version`)
- [ ] Is `loop.sh` executable? (`chmod +x loop.sh`)
- [ ] Do `PROMPT_plan.md` and `PROMPT_build.md` exist in the project root?
- [ ] Does `AGENTS.md` have the correct build/test/lint commands?
- [ ] Does `IMPLEMENTATION_PLAN.md` exist (even if empty)?
- [ ] Are there spec files in `specs/`?
- [ ] Are you on the correct Git branch?
- [ ] Do the project's tests pass before starting Ralph?
- [ ] Are you running in a sandbox or isolated environment?
